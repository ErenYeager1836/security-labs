1. SQL Injection (CWE-89)

Direct string interpolation vs Parameterized Prepared Statements.

Vulnerable Pattern

query = f"SELECT * FROM users WHERE username = '{username}'"

Allows altering SQL syntax using quotes and boolean expressions.

Remediated Pattern

cursor.execute("SELECT * FROM users WHERE username = ?", (username,))

Database driver compiles query before binding inputs as literal operands.

2. Reflected Cross-Site Scripting (CWE-79)

Unescaped HTML Reflection vs HTML Entity Encoding & Content-Security-Policy.

Vulnerable Pattern

return f"<h2>Results: {q}</h2>"

Browser parses injected HTML tags as executable script elements.

Remediated Pattern

html.escape(q) + CSP: default-src 'self'

Encodes HTML entities (&lt;, &gt;) and enforces browser-level execution policies.

3. Insecure Direct Object Reference (IDOR) - CWE-639

Direct primary key lookup vs Owner-scoped tenant queries.

Simulated Session Context: Authenticated as 'Alice' (User ID: 2).

Vulnerable Pattern

SELECT * FROM notes WHERE id = ?

Allows Alice to fetch note 3 (Bob's private note) or note 4 (Admin key).

Remediated Pattern

if note['is_private'] and note['owner_id'] != current_user.id: abort(403)

Enforces object-level authorization and restricts access to owned assets.

4. Server-Side Request Forgery (SSRF) - CWE-918

Unvalidated backend fetching vs DNS IP resolution and private CIDR blocklisting.

Vulnerable Pattern

urllib.request.urlopen(user_url)

Allows reaching internal microservices (127.0.0.1) and cloud metadata.

Remediated Pattern

ipaddress.ip_address(dns_ip).is_private or is_loopback

Rejects loopback, private, link-local IPs and disables HTTP redirects.
